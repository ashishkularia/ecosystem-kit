# CONVENTIONS — ecosystem-kit

- Python: stdlib ONLY, `python3`, no pip/venv. Tests use `unittest` (pytest may not exist on hosts). Hooks live flat in `engine/hooks/`; `_`-prefixed files are infrastructure, everything else is a dispatchable hook module.
- Shell: bash with `set -euo pipefail` (`health-check.sh` deliberately drops `-e` — its checks are expected to fail without aborting the run). `shopt -s nullglob` before glob loops.
- JSON in shell: always python3 heredocs/one-liners, never jq (not installed on hosts).
- Hook wiring: cwd-independent commands only — `python3 "$CLAUDE_PROJECT_DIR/.claude/hooks/_client.py" <hook>` — and ONLY in `.claude/settings.json`. No hooks blocks in settings.local.json or user-level settings. Never bare-relative (`python3 .claude/...`): it resolves against the shell's cwd and fails whenever a session's persistent cwd drifts out of the repo root.
- Install semantics: copy, never symlink. Engine overwrite is OK (kit-owned); knowledge (`.memory/`, `kit.json`, existing `settings.json`) is never clobbered, and neither is `CLAUDE.md` EXCEPT the text between `<!-- kit:begin NAME -->` / `<!-- kit:end NAME -->` marker lines, which `update.sh` syncs from the template (`installer/kit_blocks.py`; owner-approved 2026-10-20). A new kit-wide CLAUDE.md policy goes in the template INSIDE a block, or it reaches new installs only. Block bodies carry no `{{placeholders}}` — update.sh does not render them.
- Dates: ISO `YYYY-MM-DD` everywhere — DECISIONS entries, diary filenames, changelogs.
- No secrets in any kit file or installed file, ever.
- Protected branches: Claude never merges/pushes to main/master; the owner merges.
- `.memory/cache/` is runtime scratch: self-gitignored via a TRACKED `.gitignore` containing `*` + `!.gitignore` (so the dir survives clones; no root-level `.memory/cache/` ignore line — that would untrack the mechanism itself), recreated by installer/hooks, never carries knowledge.
- Scratch is `.claude/scratch/`, never `/tmp` (owner rule 2026-10-19): throwaway scripts, captured output, rehearsal installs, drafts. Self-gitignored the same way as `.memory/cache/` (tracked `.gitignore` with `*` + `!.gitignore`; no root-level ignore line). Hooks treat it as non-source via `_constants.is_scratch_path` — new "is this source?" logic must call that, not re-derive it. Delete your own scratch when done, as its own Bash call: `rm -rf` of literal paths under `.claude/scratch/` is exempt in `guard_dangerous_commands` (`scratch_cleanup_only` — whole line must be nothing but such removals; no globs/quotes/variables/`..`; not the scratch root). Chain it with anything else and the guard blocks it. Repos whose installed guard predates the exemption still block `-rf`; use `rm -r` there.
- Memory-roster templates and CLAUDE.md are RENDERED at install (`{{PROJECT}}`/`{{STACK}}`/`{{DATE}}`/`{{REPO_ABS}}` via install.sh `render_file`); command/agent/skill templates carry no placeholders and are copied verbatim by design. Project customization happens after install in the target repo.
