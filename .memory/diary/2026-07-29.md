## Session — hook wiring made cwd-independent (fix/hook-cwd-wiring)

Dear diary,

**Discussed:** The relative hook wiring (`python3 .claude/hooks/_client.py
<hook>`) that we chose on 2026-07-23 for portability has a real failure mode
found in the field: Claude Code's persistent Bash cwd can drift into a
subdirectory (a meritick session sat in `resources/views/`), and from there
EVERY hook dies with "can't open .../resources/views/.claude/hooks/_client.py".
A prior session's workaround — a forwarding shim copy of `_client.py` planted
in the subdirectory — was rightly rejected: it scatters dispatcher copies and
papers over the bug.

**Decided:** (mirrored in DECISIONS.md) Wire hooks through the
harness-provided project root instead:
`python3 "$CLAUDE_PROJECT_DIR/.claude/hooks/_client.py" <hook>`. Claude Code
sets `$CLAUDE_PROJECT_DIR` on every hook run and hook commands go through a
shell, so it expands regardless of cwd. This keeps everything the relative
form bought us (no hardcoded absolute or per-machine paths, clone-anywhere)
and drops the cwd dependence. Wiring-only fix — the engine already derives
its paths from `realpath(__file__)` and needed no change.

**Done:** (see CHANGELOG for the one-liner)
- `templates/settings.json.template`: all 15 hook commands rewritten to the
  `$CLAUDE_PROJECT_DIR` form (quotes JSON-escaped; `json.tool` validated).
- `health-check.sh` parity check: accepts the new prefix, still tolerates the
  legacy relative form on pre-fix installs; the name-token trick
  (`command.split()[-1]`) is unaffected — verified by simulating the exact
  snippet against a scratch install (0 problems, 12/12 hooks matched).
- Docs de-drifted: README headless-bootstrap bullet, CLAUDE.md hard rule
  (now says never bare-relative), ARCHITECTURE layout line + engine diagram,
  CONVENTIONS wiring rule, install.sh section comment, `_client.py` /
  `_constants.py` docstrings.
- Proven end-to-end: parsed the wired command out of the template, ran it via
  `bash -c` from `/` with `CLAUDE_PROJECT_DIR` pointing at a scratch install —
  session_boot executed and emitted its banner. Engine suite 94/94 green.

**Open:**
- Installed repos still carry the relative wiring until their next
  `update.sh`/manual settings merge (settings.json is skip-if-exists, so the
  installer will print a manual-merge diff rather than auto-fix). Health-check
  tolerates the legacy form meanwhile.
