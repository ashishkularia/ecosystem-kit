- [ ] 2026-08-01 — **Ship runner + CI-pipeline guidance to every repo** (owner ask; source: mylantite, which implemented self-hosted CI 2026-07-29→08-01). Two distinct needs: (a) standing up and operating self-hosted GitHub Actions runners, (b) diagnosing a failing pipeline fast. The kit has NOTHING on either today — the only "runner" match in `templates/` is "test runner" in `fix-test-failures.md`. Shape is open (skill / reference / steps); proposal below, owner rules.
  - **Why it belongs in the kit, not one repo:** two repos (mylantite, meritick) now run self-hosted runners on the same box and hit the same traps; homelab and grade5 are candidates next. This is the `docs/ARCHITECTURE.md` §8 promotion loop firing — but the source doc is project-SPECIFIC, so it must be generalized, not copied. `mylantite-ci`, `mylantite_app-network`, `/opt/ci-deps` are specifics; the principles under them are universal. Copying the doc would ship mylantite's topology to homelab — the per-project fork CLAUDE.md warns against.
  - **Proposed split, by nature of the content** (mirrors how the kit already separates artifacts):
    1. `templates/skills/ci-triage.md` — the diagnostic LOOP, modelled on `fix-test-failures.md` (symptom → likely cause → the command that distinguishes them). Stays project-agnostic by reading `kit.json` + the project's own `.memory/contexts/ops-ci.md`, exactly as `fix-test-failures` reads `quality_commands.test`. **The smallest useful version — build this first.**
    2. `templates/memory/contexts/ops-ci.md.template` — the SHAPE each repo fills in (which jobs run on which runner and why; definition-of-done for a CI change), asserting no repo's topology. Cheap and high value: mylantite's version already proves the shape works.
    3. `templates/memory/references/self-hosted-runners.md` — generic invariants, only if they exceed a page. Candidates: *jobs must not assume tools on the runner host* (run inside the app image; if a job needs a tool it goes in the image, not on the box); *tag a CI image with a hash of the dependency manifests* so a stale image can never be used silently and a mismatch degrades to slow, never to wrong; *keep CI logic in committed `.github/ci/*.sh`, not inline YAML*, so local reproduction is one command; *never move deploy/e2e onto a self-hosted runner* (browser deps need sudo; deploy creds stay off the dev box).
  - **Concrete gotchas the guidance must carry** (all real, all cost time): a nohup'd runner does not survive reboot — meritick's runner ran from `~/actions-runner-staging/meritick-1` and its CI dies on restart, while mylantite's is a systemd unit (see meritick VERIFY, 2026-07-29); one runner per repo was an owner decision because a true shared runner group needs an ORG and both repos are personal-account; `git archive` is the WRONG way to reproduce a cold checkout when `.gitattributes` has `/.github export-ignore` — the archive silently omits the very `.github/ci/*.sh` under test and the run dies `exit 127, No such file` (use `git clone --depth 1`); `npm ci` needs `--legacy-peer-deps` at every call site when a plugin peer-caps below the repo's eslint; a self-hosted runner sharing the dev DB/Redis can collide with a live dev session; cold checkouts surface what warm caches hide (a stale `phpstan.neon` ignore only appeared under container CI).
  - **Sources to mine when building:** mylantite `.memory/contexts/ops-ci.md` (the best single artifact), its PR #25 body, DECISIONS 2026-07-29 CI-runner entry, `.github/ci/*.sh`, and the `chore(ci): preinstall deps in a hashed CI image` / `fix(ci): pass --legacy-peer-deps` / `fix(ci): placeholder Stripe creds` commits; meritick's runner-topology VERIFY entries and `restructure-runners.sh` (needs rewriting for the two-runner topology before it is run).
