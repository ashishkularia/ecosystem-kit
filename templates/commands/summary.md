Produce a work-planning digest.

1. Read `.memory/ISSUES.md`, `.memory/IDEAS.md`, `.memory/VERIFY.md`, and
   `.memory/CHANGELOG.md` (recent momentum).
2. Group open issues by theme (cleanup / security / reliability / UX) and
   rate each: effort (S/M/L), risk, and what it unblocks.
3. Check VERIFY.md for anything whose gate has likely passed since it was
   written (the deploy happened, the time window elapsed) — verifying those
   is usually the cheapest win.
4. Recommend a top-3 "do next" list with one-line reasoning each, and flag
   any idea whose prerequisites have recently become available.
5. Output is advisory only — change nothing.
